## 目标

1. 建立 trust-first 使用闭环：`explain`、`adopt --dry-run`、`outdated`。
2. 保持所有权边界：`upgrade --all` 只处理 hukou 收编条目；全机升级仅提供 Topgrade 集成。
3. 关闭高价值可靠性债务：确定性激活历史、history-aware retention、版本策略、窄版 repair 和脱敏 support bundle。
4. 完成公开准备：英文默认界面、许可证与第三方 notices、社区文件、安装器、CI/发布供应链配置。

## 关键安全不变量

- `scan`、`explain` 与 adopt dry-run 零网络、零 hukou 状态写入。
- `outdated` 只访问 release metadata，零下载、零本地写入。
- 真实写操作在锁内重新检查现场，不信任旧计划。
- history 与当前 manifest 必须在同一持久化事务中提交。
- retention 不依赖目录 mtime，不删除 current、original、pin 或受保护历史目标。
- repair 必须 plan/apply 分离并绑定状态指纹；plan 会写用户指定的输出文件，apply
  可能创建/使用锁文件，但 stale plan 不得修改 live、store、manifest、backup 或
  journal 等业务状态。这里的保证是“零业务状态写入”，不是“绝对没有文件写入”。
- support bundle 默认脱敏、无网络、不自动上传。
- 外部管理器继续拥有自己的工具，hukou 不伪造跨管理器回滚保证。

- schema v1→v2、历史 rollback、retention、pin/channel/SemVer 测试。

- macOS 本机、Linux 原生容器、四目标构建、双构建一致性。
- 安装器错误平台、坏 checksum、网络中断与临时前缀 smoke。
- release snapshot 的 LICENSE/notices/SBOM/checksum/buildinfo 检查。
- 文档链接、workflow YAML、shell syntax 与社区文件检查。

## 风险与回滚

- Manifest v2 是兼容边界；V0.2 必须拒绝读取而不是丢字段，迁移前保留可恢复备份。
- 新 repair 写路径只开放能证明前置条件的动作，任何不确定状态失败关闭。
- 所有实现位于独立分支并分主题提交；未通过门禁不合并、不打 tag。
- private 仓库的 GitHub-hosted Actions 仍可能被 Billing 阻断；本轮记录为 RC 外部门禁，不以本地验证冒充远端绿色。
- 公开、许可证发布效果、公开配套仓库与正式 Public Beta 均需后续独立 Go/No-Go，不在本次授权范围内。
