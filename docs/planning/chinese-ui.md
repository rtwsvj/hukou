## 一、要干什么

把 hukou 在终端里显示给"人看"的文字全部翻译成中文。注意两条线：

- **人看的文字**：翻译（帮助、表格、报错、通知……）。
- **机器读的数据**：不动（程序之间互相传的编号、字段名保持英文，否则会乱套）。

默认仍显示英文（这是项目一贯规矩，也方便国外用户）；想用中文的人打开一个开关即可。

## 二、现状盘点：一共要翻多少

把代码里所有给人看的文字数了一遍，分五类：

| 类别 | 大约多少条 | 人话说明 |
|---|---|---|
| 命令帮助和按钮说明 | 约 80 条 | 每个命令的说明文字、每个开关的解释 |
| 表格和总结 | 约 60 条 | 盘点结果表的表头、底部统计行 |
| 体检报告 | 约 110 条 | doctor 命令输出的每条诊断；**每条都有编号**（编号保持英文），翻译只换文字 |
| 报错信息 | 约 600 多条 | 各种"出错了"的提示，量最大、最零散 |
| **合计** | **约 700–850 条** | 大部分都带着变量（比如"已升级 某程序：1.0 → 2.0"里的名字和版本号不用翻，只翻固定文字） |

（另有一类"程序来源说明"，约 60-100 条，是翻译里最难的——每条都是拼接的短语。你已同意**暂缓**，先不做。）

## 三、做法：抄 topgrade 的作业

13 个同类软件里只有 topgrade 做了中文界面，它的做法就三样：

1. **一张中英对照表**：每条英文原文 → 一条中文翻译，全部存在一个表里。
2. **一个语言开关**：看用户系统语言自动选（也可以手动指定），选不到就默认英文。
3. **缺翻译自动兜底**：表里没有的句子，直接显示英文原文，程序不会因此出错。

hukou 照抄这三样即可，而且有一个现成优势：**项目里已经有一份中文说明书**，里面把专业名词都定好了——"黑户""收编""血缘""回滚""户口本"。中文界面直接沿用这套词，不用重新造词，将来也不会前后不一致。

### 具体技术方案（给执行者看）

- 新建一个"词表"模块（`internal/i18n`），用**英文原文当钥匙**：程序里写 `翻译("Adopted %s")`，词表里查得到就显示中文，查不到就显示英文。这样 700 条文字不需要另外编一套编号（体检报告例外：它自带编号，直接用编号当钥匙）。
- 语言怎么选（优先级从高到低）：
  1. 环境变量 `HUKOU_LANG`（用户显式指定，如 `HUKOU_LANG=zh`）；
  2. 系统语言（`LANG`/`LC_ALL`）；
  3. macOS 上还有系统界面语言兜底（`AppleLocale`/`AppleLanguages`，中文系统自动出中文界面，无需任何设置；解析失败时安全忽略）；
  4. 都没有 → 英文（默认，不变）。
- 零新依赖：词表就是 Go 语言自带的数据结构（map），符合项目"尽量只用标准库"的规矩。

## 五、已知的坑（提前说清楚）

1. **中文比英文"宽"**：表格是按字母宽度排版的，中文会让列对不齐。需要修一下排版逻辑（判断"这个字占两个字母宽"），这是整个方案里唯一有点技术难度的活。
2. **测试里的旧文字**：项目有大量自动化检查，很多检查拿"英文原文"当对错标准。翻译后这些检查会误报——要把它们改成"看编号/看类型"而不是"看文字"。执行时默认让检查跑英文模式，再单独加中文模式的检查。
3. **报错文字零散**：600 多条报错分散在几十个文件里，没有捷径，只能逐个改。这是第③步慢的原因。
4. **翻译质量兜底**：加一道自动检查——词表里"有钥匙就必有中文"，缺了就报错提醒，防止以后新加文字忘了翻译。

## 六、验收标准（做完长什么样）

- 打开中文开关后：帮助、盘点表、体检报告、报错——全中文。
- 关掉开关（或没设置）：和现在一模一样，全英文。
- 两种模式下，程序功能、对错判断、机器读的数据完全不变。
- 文档同步：中文界面上线后，把英文说明书对应的部分更新，并说明"怎么开中文"。

## 七、不做的部分（边界）

- 不动机器读的数据（编号、字段名、JSON 输出）。
- 不改默认语言（默认仍英文）。
- 第④步（程序来源说明）暂缓。
- 不改任何功能逻辑——本次只动"显示文字"，别的一律不碰。
